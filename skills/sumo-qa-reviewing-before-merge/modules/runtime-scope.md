# Reviewing before merge: runtime scope and the trivial-change exemption

Lazy module of `sumo-qa-reviewing-before-merge` (load via `sumo_qa_load_skill_context` with `mode="module"`). **Load when:** deciding whether a diff is a runtime change (the executable-behaviour rule, not path or file type) or qualifies for the trivial-change exemption; always load for a diff touching hooks, scripts, CI/workflow steps, automation, or docs/static config. **Extends:** the runtime-change trigger in Verdict-format discipline and checklist step 4. The root's Iron Law, verdict gate, and output discipline apply unchanged.

## What counts as a runtime change (pinned)

**What counts as a runtime change (pinned):** the classifications catalogue's executable-behaviour rule (loaded at step 3) decides it per changed file, never path or file type. Runtime includes a hook under `.claude/hooks/`, a `scripts/` script, a `.claude/` automation or generated runner, a CI/release workflow shell step, a Makefile/justfile recipe, a git hook, executable test infrastructure under `tests/` (per `test-only-diff`), and a procedure an agent or operator follows, for each change that rule makes runtime. **Dependency constraints (one rule):** a manifest or lock change to a dependency that runtime code in the repo imports, directly, transitively (a lock entry beneath an imported package) or by dynamic load, or to the interpreter or base image that code runs on, is a runtime change, because it changes what that code runs on: sweep + ledger, the risk anchored at the importing code, COVERED only by fresh tests that exercise it on the new version. A constraint on a package nothing at runtime imports, reaches or runs on (a dev, test or lint tool), and the project's own version string or name lists, are metadata: the inventory-drift rule's, not promoted to runtime on their own.

**Procedure probe (pinned):** for each changed command or step in a procedure an agent or operator follows, run three checks, each hit a risk at file:line: run each command as written against the tool that reads it (a path or glob it does not expand, quoting); list every value a step reads, sentinel and empty values included, and name any with no branch; trace each value or state one step hands to the next and confirm it survives the hand-off. Lint and link checks do not cover these; a dry run through the procedure's branches does, else UNCOVERED.

## Command/input-classifier probe (pinned)

**Command/input-classifier probe (pinned):** when the change adds or edits a predicate that classifies a command or string (`split()` plus token membership, `in`, `startswith`, a regex), probe it BOTH ways against the function's stated PURPOSE, not its mechanism line. False positive: the token as an argument or inside echoed or quoted text (`echo "run pytest later"`, `grep pytest log`). False negative: an equivalent form the match misses (alternate or legacy entrypoint, path-prefixed or suffixed token such as `/usr/bin/pytest`, the `python -m` form). A docstring or comment restating the naive rule describes the defect; it is not a spec that clears it. Each confirmed mis-classification is a named risk with its own ledger row. A green test feeding only the canonical command is path-matching but not at the failure mode, so that risk is UNPROVEN, never a residual concern. `Named risks: None` on a command-parsing change is the waved-through failure.

## Location claim (pinned)

**Location claim (pinned):** when the requester or PR calls a change trivial, tooling, or non-runtime because of WHERE it lives ("just a hook", "not under src", "only a script"), answer that claim in one line of the review: location does not decide runtime scope, executable behaviour does, then name the behaviour that makes THIS change runtime (e.g. the hook parses every Bash command and gates it). Running the sweep without saying so leaves the requester's rule standing for the next diff; silence is not a rebuttal.

## Trivial-change exemption (pinned)

**Trivial-change exemption (pinned):** for **genuinely non-executable diffs**, NOT "anything outside `app`/`src`/`lib`". A diff qualifies only when each change is prose-only by the executable-behaviour rule (docs or comments, in a procedure doc too), static/inert config (YAML/TOML/JSON read as data, not executed — formatter/linter ignore lists, editor config), or in other files with **no executable behavioural surface**. A dependency constraint change qualifies only when runtime code neither imports, reaches nor runs on it (the dependency-constraints rule in "What counts as a runtime change"). Path is irrelevant: an executable hook/script/automation does NOT qualify (run the full sweep + ledger). When the diff DOES qualify: SKIP item 2; the verification command (linter/formatter/build) IS the coverage, so mark those anchors `COVERED BY VERIFICATION`. The exception is a stale mirror `mirrored-constraints` finds: the verification command does not run its isolated environment, so it still gets its UNCOVERED 2a row and its item-8 line, each a SAFE-blocker, in this mode. Items 1, 3, 4, 5, 6 still required. An exempt diff names no risk in unchanged content: no residual "re-verify" of untouched commands. `Touched files:` and `Change shape:` are mandatory in both modes; citing the verification command's file argument does not discharge `Touched files:`.

## Red Flags

| Thought | Reality |
|---|---|
| "Only `pyproject.toml` and the lock changed, no code: trivial" | A bumped runtime dependency changes what the importing code runs on. Name the consumer's risk (file:line) and map it to the fresh tests that exercise it on the new version. |
| "This hook/script is under `.claude/hooks/` or `scripts/`, not `app/src/lib`, so it's trivial — skip the sweep" | Path does not decide; the executable-behaviour rule does. Run the full sweep + ledger: the command-parsing defects (echo-token, flag-arity, quote-splitting) hiding in such hooks are exactly its target class. |
