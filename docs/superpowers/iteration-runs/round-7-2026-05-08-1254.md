## What the new fields demonstrated in practice

The grading subagents specifically used the new fields where applicable:

- **`do_not_test`** — every scenario where it applied populated 2-4 senior-voice "skip these" entries with `why_not`. Examples: "DAST scans against in-process validator (no HTTP surface)", "exhaustive permutations of unreachable rule combinatorics", "mutation testing on synthetic Kotlin `object` accessors", "tautological tests that re-state the config value", "UI snapshot tests for backend feeders", "generated Feign client interfaces (drive via Pact instead)".
- **Stable scaffold IDs** (`T*` / `U*` / `B*` / `"NONE"`) — the scaffold-bundle-validator scenario emitted 5 top_risks each linked via stable id (`T5`, `U1`, `U2`, `U3`, `B1`) — every risk traces to a covering scaffold instead of dropping to `"NONE"`.
- **`characterization_tests`** — the refactor-pricing-pipeline scenario emitted 3 entries each with `test_name`, `technique`, `current_behaviour_pinned`, `fails_after_extraction_if` — exactly what a senior QA would write before the extraction.
- **`next_action.deliverable`** — spike-throwaway routed to `"captured_conditions_and_fit_record"` with `tool: null, skill: null`; docs-only routed to `"static_review_completed"`. No more shoehorning into scaffold tool.
- **Question tool `strategy_extension`** — the how-to-test-this-service scenario produced full `pyramid_shape` / `gate_calibration` / `ci_feedback_time` / `rollout_plan` from the question tool path, matching the depth `decide_approach` would produce.
- **Prepare-tool harmonisation** — security-token-refresh now emits `principle_cited`, `top_risks` (5), `named_techniques` (5), `smallest_useful_tests` (5), `do_not_test` (2), `assumptions` (4) — was previously bare narrative + checks.
