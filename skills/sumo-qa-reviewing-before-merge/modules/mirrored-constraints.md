# Reviewing before merge: mirrored dependency constraints

Lazy module of `sumo-qa-reviewing-before-merge` (load via `sumo_qa_load_skill_context` with `mode="module"`). **Load when:** the diff changes a dependency, tool or runtime constraint, runtime or trivial diff alike; load `inventory-drift` (2a rows; what is not an anchor) and `surface-verifier` (item-8 line format) with it. **Extends:** checklist steps 4 and 9 (2a rows) and Verdict-format item 8. The root's Iron Law, verdict gate, and output discipline apply unchanged.

## Mirrored-constraint probe (steps 4 and 9)

**Mirrored-constraint probe (pinned).** When the diff adds, removes, floors, ceilings or pins a dependency, tool or runtime constraint, the same constraint is often copied into an isolated environment the application suite never runs, so a green suite proves nothing about it. Search by the dependency's identity, classify each occurrence before judging it, and name every stale mirror as its own 2a row plus the exact command that runs its environment's own install/smoke check. Run it even under the trivial-change exemption: a manifest-only bump is exactly where the stale mirror hides.

1. **Search by identity.** Search for the canonical package/tool name and its spelling variants (`-`/`_`, case), not only the old version string. Check every applicable location: manifests, extras/groups, lock and constraints files; pre-commit/pre-push hook `additional_dependencies` and other isolated hook environments; CI install commands, setup-action versions and tool pins; Docker/devcontainer base-image tags; bootstrap, release, build and tox/nox scripts. The list is a floor. A search that skipped hidden files (`.pre-commit-config.yaml`, `.github/`, `.devcontainer/`) is incomplete: say so.
2. **Classify before judging.** Give each occurrence one relationship: declared mirror, a range in another environment or supported runtime, deliberately independent environment (a documented reason), generated lock/resolution, or prose only (changelog, ADR, release notes). A **declared mirror** has a keep-in-sync/lockstep statement on its line, its enclosing block or its file header, or a guard test or policy in the supplied context enforcing equality for that pair; nothing else makes one, the same text included. A generated lock is judged by its resolved version; a historical record states what was true then, so it gets no 2a row, no residual note asking to refresh it, and is never rewritten.
3. **Compare semantics, not text.** A declared mirror is held to both ends: stale when either bound differs from the diff's, a raised ceiling included (manifest now `>=1.2,<3`, keep-in-sync hook `<2`). Any other occurrence is stale only when its range shares no version with the diff's range, a lock or already-built environment resolves outside it, or its environment runs the changed code the new bound exists for (a hook or CI job running that suite) while still admitting versions the bound excludes. A range for another runtime or audience that shares versions is compatible: `<3,>=2.4` and `~=2.4` both fit `>=2.4`, so syntax, order or an undeclared narrower cap is not drift, a risk needing a release that does not exist yet is speculation, never a named risk or residual, and one shared upper bound is never demanded. An independent environment keeps its documented reason.
4. **Anchor each stale mirror.** Only an occurrence step 3 finds stale gets its own `inventory-drift` 2a row with the constraints as the value pair, e.g. `Inventory drift anchor: tox.ini:12 (>=2.0 → >=2.4) | Required update: this file | Diff updated it: NO | Coverage: UNCOVERED`; beside it, a compatible sibling keeps only its relationship line, never a residual.
5. **Verify each isolated environment.** Fixed text does not prove the environment runs, so each isolated environment the diff changes or must change (a stale mirror's, never a compatible sibling's) gets its own Verdict-format item-8 line, UNVERIFIED and a SAFE-blocker until its own install/smoke run is supplied fresh; the application suite's run never discharges it. Reading a guard or predicting its result is not a run: until its output is supplied the line stays `Ran: NO`. Emit it in exactly this shape, the stale mirror's file in the parentheses:
   `Surface verifier: <the environment's own run: hook run after a rebuild, image build, CI job> (<stale mirror file>) | Ran: NO | Status: UNVERIFIED (surface verifier), SAFE-blocker`
   e.g. `Surface verifier: pre-commit run mypy --all-files (.pre-commit-config.yaml) | Ran: NO | Status: UNVERIFIED (surface verifier), SAFE-blocker`. BAD: `the mypy hook environment` (never a description of the environment), or only a guard script (it checks text, not the environment).
   The verdict line names that command, and any guard declaring the mirror, as what clears the blocker, beside the file update.

**No mirror to fix (pinned).** When the search finds no second occurrence, or only compatible, independent, generated or prose ones, record each relationship in one line and raise no synchronisation requirement: no 2a row, no named risk, no residual asking to align or refresh them. Manufacturing one is the over-trigger. The residual item follows `inventory-drift`'s constraint-diff residual rule.

## Red Flags

| Thought | Reality |
|---|---|
| "The suite is green, so the dependency bump is proven" | A hook, image or CI job holding a stale mirror is unverified until its own run. |
| "The hook caps `<4`, the manifest is uncapped: when 4.0 ships they diverge, so add a risk, a residual, or cap the manifest now" | 4.0 does not exist; both ranges admit what the diff requires and exclude what it forbids, so neither is stale. That divergence is not a risk or residual and caps neither side; the change's own runtime risks stay named at the importing code, and the residual is an input the fresh runs skipped. |
