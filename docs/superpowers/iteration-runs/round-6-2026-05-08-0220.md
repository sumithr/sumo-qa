## Backlog observations the graders surfaced (non-blocking)

The grading subagents called out a few quality-of-life items that
become visible now that the strictest schemas (question + decide +
review) are aligned. None block senior-grade; recording for backlog:

1. **Prepare-tool schema is still less strict** than question / review.
   `_build_prepare_sampling_prompt` doesn't yet require structured
   `principle_cited`, `top_risks`, `named_techniques` — the fields are
   present in the system prompt's HARD REQUIREMENTs but not yet
   reflected in the prepare-tool's per-call schema. Round-6 harmonised
   review; the same harmonisation could land on prepare next.
2. **`qa_answer_testing_question` strategy-orchestration response** —
   when the question tool routes to strategy-orchestration via
   `recommended_approach`, the schema doesn't currently require the
   extension block (`pyramid_shape` etc.). The user gets a tight
   "load the strategising skill" answer; the deeper fields land in
   `qa_decide_approach` only. Could be extended.
3. **`scaffold_coverage_task_id` linkage** between scaffold's
   `top_risks` and `uncovered_branches` is convention rather than
   schema-enforced. A stricter schema would require the link by ID.
4. **Explicit "what NOT to test"** is in the system prompt as senior-QA
   discipline but isn't a structured field on any tool's schema. For
   open-ended questions this is easy to drop.
5. **`spike-first-then-tests`** routes via `next_action.tool =
   "sumo_qa_scaffold_tests"` because there's no dedicated tool for
   "capture spike conditions". Awkward but not wrong.
6. **`coverage-first-then-refactor`** doesn't formally require a
   characterization-test field. The model produces it via narrative
   pressure, but a dedicated `characterization_tests` slot would lock
   it in.
