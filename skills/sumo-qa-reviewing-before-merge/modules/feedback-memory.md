## Review-feedback memory (advisory hints only)

A team can promote a recurring review lesson into an EXPLICIT, user-confirmed local memory (`sumo_qa_capture_review_feedback`, stored under the #92 user-pack `feedback/` subdir). When present, consult it as a HINT source that sharpens the discovery sweep (step 4) — never a blocker or authority. Apply a stored lesson only when its `trigger_signal` matches THIS diff's change shape; surface it SEPARATELY as its own labelled line, QUOTING the matched `trigger_signal` and `recommended_probe` VERBATIM (never paraphrased — a loose paraphrase the reviewer can't trace to the supplied block is a grounding failure): *"advisory hint from saved review feedback (trigger: <trigger_signal>): <recommended_probe>"*, distinct from the catalogued ISTQB/techniques/loaded change-rules. A matched hint becomes an ordinary named risk, mapped through the coverage ledger like any other (the verdict gate, step 10, is unchanged); it NEVER overrides a canonical classification or change-rule (only a #92 custom pack carries that authority). Absent/empty memory: emit the root's pinned one-liner (checklist step 4) and run the normal sweep — NEVER invent, infer, or recall a hint. Do NOT auto-capture from this review: saving a lesson is a separate, explicit, user-confirmed step storing only the user's own short summary (never a raw diff, secret, code snippet, or pasted issue/PR body — the tool rejects those).
