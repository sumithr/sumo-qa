# Reviewing before merge: mirrored dependency constraints

Lazy module of `sumo-qa-reviewing-before-merge` (load via `sumo_qa_load_skill_context` with `mode="module"`). **Load when:** the diff changes a dependency, tool or runtime constraint, runtime or trivial diff alike; load `inventory-drift` (2a rows) and `surface-verifier` (item-8 line format) with it. **Extends:** checklist steps 4 and 9 (2a rows) and Verdict-format item 8. The root's Iron Law, verdict gate, and output discipline apply unchanged.

## Mirrored-constraint probe (steps 4 and 9)

**Mirrored-constraint probe (pinned).** When the diff adds, removes, floors, ceilings or pins a dependency, tool or runtime constraint, the same constraint is often copied into an isolated environment the application suite never runs, so a green suite proves nothing about it. Search by the dependency's identity, classify each occurrence before judging it, and name every stale mirror as its own 2a row plus the exact command that runs its environment's own install/smoke check. Run it even under the trivial-change exemption: a manifest-only bump is exactly where the stale mirror hides.

1. **Search by identity.** Search for the canonical package/tool name and its spelling variants (`-`/`_`, case), not only the old version string. Check every applicable location: manifests, extras/groups, lock and constraints files; pre-commit/pre-push hook `additional_dependencies` and other isolated hook environments; CI install commands, setup-action versions and tool pins; Docker/devcontainer base-image tags; bootstrap, release, build and tox/nox scripts. The list is a floor. A search that skipped hidden files (`.pre-commit-config.yaml`, `.github/`, `.devcontainer/`) is incomplete: say so.
2. **Classify before judging.** Give each occurrence one relationship: declared mirror (declared lockstep: a keep-in-sync comment, or a guard or policy enforcing equality), a range in another environment or supported runtime, deliberately independent environment (a documented reason), generated lock/resolution, or prose only (changelog, ADR, release notes). A generated lock is judged by its resolved version; a historical record states what was true then, so it gets no 2a row, no residual note asking to refresh it, and is never rewritten.
3. **Compare semantics, not text.** Only an occurrence whose own line or file declares lockstep is a declared mirror, held to both ends: stale when either bound differs from the diff's, a raised ceiling included (manifest now `pytest-cov>=6,<8`, keep-in-sync hook `<7`). Carrying the same text, even the diff's old text, does not make a pin one. Every other range is judged by what it admits: `<3,>=2.4` and `~=2.4` both fit `>=2.4`, so syntax, order or an undeclared narrower cap is not drift, and a release that does not exist yet is no present defect: never demand one shared upper bound. Such a range is stale only when it still admits versions the diff excludes, or shares no version with the diff's range (a lock's resolved version is not that range); an independent environment keeps its documented reason and is not held to the diff's range. A risk that needs a future release, such as one breaking an uncapped side beside a capped pin, is speculation, not a named risk or a residual.
4. **Anchor each stale mirror.** Only a stale occurrence gets its own `inventory-drift` 2a row with the constraints as the value pair, e.g. `Inventory drift anchor: tox.ini:12 (>=2.0 → >=2.4) | Required update: this file | Diff updated it: NO | Coverage: UNCOVERED`; beside it, a compatible sibling keeps only its relationship line, never a residual.
5. **Verify each isolated environment.** Fixed text does not prove the environment runs, so each isolated environment the diff changes or must change gets its own Verdict-format item-8 line, UNVERIFIED and a SAFE-blocker until its own install/smoke run is supplied fresh; the application suite's run never discharges it. The verifier field is the command someone runs to clear it (the hook run after a rebuild, the image build, the CI job), never a description of the environment:
   - BAD: `Surface verifier: the mypy hook environment | Ran: NO | ...`
   - GOOD: `Surface verifier: pre-commit run mypy --all-files (hook environment rebuilt) | Ran: NO | Status: UNVERIFIED (surface verifier), SAFE-blocker`
   The verdict line names that command as what clears the blocker, beside the file update.

**No mirror to fix (pinned).** When the search finds no second occurrence, or only compatible, independent, generated or prose ones, record each relationship in one line and raise no synchronisation requirement: no 2a row, no named risk, no residual asking to align or refresh them. Manufacturing one is the over-trigger. The root still needs one concrete `Residual concerns:` item: take it from an unexercised code path or input, never from differing caps, syntax or history among compatible occurrences.

## Red Flags

| Thought | Reality |
|---|---|
| "The suite is green, so the dependency bump is proven" | A hook, image or CI job with its own constraint copy is unverified until its own run. |
| "The hook says `<4,>=3.1` but the manifest says `>=3.1`: inconsistent, and 4.0 could break the uncapped one" | Compare semantics. Both admit what the diff requires and exclude what it forbids; an undeclared cap in one environment is not drift, and 4.0 does not exist yet. Cap neither side. |
| "The CI pin still reads the old `<7` like the stale hook: stale too" | The declaration covers its own line only. Old text or skew between environments is not drift: the CI range shares versions with the diff's, so no 2a row, item-8 line or residual. |
| "I need a residual concern; the CI pin is tighter than the manifest, so I'll suggest aligning them" | That is the manufactured sync requirement, moved into the residual line. Name an unexercised code path or input instead. |
| "The changelog still says the old version: stale" | History: leave it as written. |
